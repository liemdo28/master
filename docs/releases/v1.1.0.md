# Mi Personal OS v1.1.0

Release SHA: `d44c705db4173e087a871e191d4087b9923280f6`

v1.1.0 releases Phase 5A: Personal OS foundation on top of the v1.0 coding baseline.

## Included

- Durable personal preferences.
- Durable goals with explicit state transitions.
- Approval-gated goal planning.
- Daily brief records with facts, suggestions, and unknowns.
- Child tasks created through the existing Task Runtime.
- Project validation through the existing Project Registry.
- Strict API-key authentication for personal APIs, including localhost.
- Restart persistence for preferences, goals, plans, child task links, and daily briefs.

## Safety Boundary

Phase 5A does not execute planned child tasks. Child tasks are created at `WAITING_APPROVAL`, and goal activation or pause never runs code, push, merge, deploy, email, publish, or any external action.

Repeated planning returns the existing plan and child task IDs. Partial child-task staging uses recoverable operation records and retry dedupe.

## Data

Runtime databases are outside source control under `.local-agent-global`:

- `.local-agent-global/personal-os/personal-os.db`
- `.local-agent-global/task-runtime/tasks.db`
- `.local-agent-global/project-registry/projects.db`

The Personal OS database stores visible records only: preferences, goals, plans, priorities, daily briefs, events, and plan operations. It does not store hidden chain-of-thought. Secret-like inputs are rejected and daily brief summaries redact credential-shaped text.

## Known Limitations

- No semantic personal knowledge memory yet.
- No calendar or email intelligence.
- No voice.
- No unrestricted desktop control.
- No autonomous push, merge, or deploy.
- No autonomous external actions.
- No Phase 5B long-term memory in this release.
